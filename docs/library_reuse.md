# 社区库复用与适配边界

项目优先复用已有成熟社区库和Python标准库。算法或协议核心由库维护，项目代码负责数据组织、来源追踪及明确需要的适配。新增依赖应有必要性；不为几行项目编排引入大型框架。

## 本次重构

- BM25：统一依赖rank-bm25的BM25Okapi计算词频饱和、长度归一化和评分；删除手写稀疏BM25核心。预处理通过一个小型IDF适配保留此前的正IDF定义，并保留查询去重、未见词惩罚和评分上界归一化，以维持既有分数口径。在线检索仍调用该库的默认BM25Okapi，两条路径的IDF策略不同，但不再自行实现核心评分。
- API重试：使用Tenacity配置可重试异常、最多retries+1次尝试及1、2、4秒封顶的指数退避，保留逐次调用记录、缓存及最终错误类型。禁用SDK内置重试，避免与应用重试叠加，实际请求次数由应用预算控制。
- JSON块识别：使用标准库JSONDecoder.raw_decode定位ES mapping边界，删除两处手写字符括号计数，正确处理字符串和注释中的花括号。

## 保留的自定义代码

- 正IDF与得分归一化是已有预处理评分协议的兼容适配，不是另一套BM25核心。
- JSON的双斜杠注释及其原始位置不能由标准JSON解码器提供；保留小型注释遮蔽扫描，并将结构解析交给JSONDecoder。该扫描保留字符串、偏移和行号，注释到字段的归属仍需唯一性检查。
- 原始资料混合SQL、ES请求标记和自然语言标题，分段及来源关联属于项目输入适配；SQL语法解析继续使用SQLGlot。
- table–knowledge匹配策略、预算裁剪、简短RRF计算属于项目逻辑，不因复用原则而强制引入检索服务或大型框架。

本次不重跑训练、LLM或关联评估，不改写原始数据、现有预处理产物及冻结答案。验证采用离线数值对照、Schema解析保真和模拟API失败测试。

## 验证记录

本次63项离线测试通过；随机语料在三组BM25参数下与旧实现数值一致（容差1e-12），两份原始Schema的全部解析输出与重构前一致。模拟重试验证异常范围、等待序列、调用上限和缓存行为，无真实API请求。

一次100个原始问题×247条原始知识的小样本测时：旧稀疏实现约0.019秒，rank-bm25适配约0.090秒；数值一致。该测时不是完整流程性能评估，但说明复用现有库会带来一定评分开销，后续如需优化应先测量实际瓶颈，不重新复制核心公式。
