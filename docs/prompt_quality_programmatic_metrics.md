# 提示词程序评价指标、计算方式与设计依据

本规范细化[提示词质量评价方案](prompt_quality_evaluation_plan.md)。评价对象是最终发送给生成模型的完整提示词，指标计算不需要LLM作裁判。必须事实、适用范围和允许的替代证据需要先形成经核定的结构化基准；没有基准的项目只做工程检查或输出未知，不能凭相似度补出语义真值。

这是指标规范，尚未实现完整评价器、建立100题事实金标或产生新评分。示例数值均为演算。

## 1. 三类指标与共同约定

| 类型 | 输入 | 可以评价什么 |
| --- | --- | --- |
| A：无需题目语义标注 | 实际请求、原始资料、索引、检索日志、分词器 | 保真、索引完整性、长度、精确重复、请求一致性及运行稳定性 |
| B：需要冻结的结构化基准 | A类输入＋必须事实、合法证据路径、范围/冲突规则、相关性标签 | 必要信息覆盖、可回答性、关键矛盾、知识排序、已标注噪声、多库支持 |
| C：可选端到端验证 | 生成查询、已核定任务、参考结果或数据库 | 当前数据上的查询正确率和提示词对照效果；不直接当作输入质量 |

共同规则：

1. 使用最终实际消息，召回过但未发送的内容不算提示词证据。prepared缓存不能在没有发送边界记录时冒充真实请求。
2. 每个比例同时输出分子、分母、未知数和不适用数；分母为0记`NA`。未知不算正确，也不自动算错误。
3. 逐题宏平均为主，同时给出微平均。宏平均防止大题压过小题，微平均揭示总体事实遗漏量。
4. 参数/版本比较使用相同题集、来源、任务约定和金标。不能逐版本删除难题改变分母。
5. 生产算法不能读取评价标签。金标知识ID只在离线评价入口使用。
6. 指标记录方向：↑越高越好，↓越低越好，◇诊断量，不单独表示质量。来源忠实不等于原始内容正确，检索分数也不是质量分数。

## 2. 基准与程序匹配的定义

### 2.1 统一符号

- `Q`：全部抽样题，`N=|Q|`。
- `Q0`：原始资料、任务约定和必要事实清单已经核定的固定题集；其余题按源资料未决、金标未完成分别计数。
- `Pq`：题q实际发送的完整消息；`Eq`为其中证据内容，不含system指令和用户问题本身。
- `Fq`：必须业务事实集合，按语义去重；不包括可由题目和通用SQL/DSL能力自行推得的查询写法。
- `Hq`：核定的合法证据路径。每条路径包含需要的结构事实、适用范围，以及支持每项业务事实的证据组合。
- `D/T/C/J`：业务库、表、字段、必要关系集合。引擎集合记`E`；业务库用`引擎:命名空间`标识。
- `Gq`：已确认与题q相关的知识记录集合，用于知识记录检索指标；它不是必须事实集合。
- `Sq,s`：知识在检索阶段s的来源ID集合。
- `I(condition)`：条件成立为1，否则为0；条件未知则保留未知状态。

业务事实应是缺少就需要猜测的信息，例如专用类别阈值、单位换算约定、地标坐标。不能把“模型需要写GROUP BY”“需要规划轨迹计算”等所有推理步骤都标成提示词必须额外告知的知识，否则评价会变成要求提示词包含参考SQL。

结构事实也按实际需求确定：完整DDL覆盖作为诊断指标；若经核定案例已经明确提供某条合法查询路径的全部必要结构信息，主可回答性可以接受该替代证据。案例提到表名不等于已经提供其完整DDL、类型、可空性及全部字段。

### 2.2 事实支持使用AND/OR组合

对事实f，基准允许一个或多个支持方案。例如：

`BPS公式有依据 = 知识原文提供完整公式 OR 适用案例提供等价公式`。

`超大规模定义完整 = 床位阈值正确 AND 年门诊量阈值正确`。

一个支持方案可以同时需要多段信息，不能只命中任意关键词就算覆盖。每条合法路径h内：

`support(q,h,f) = OR(每个支持方案中的所有证据原子均存在、正确且适用)`。

对证据原子使用三值判断：

- `T`：程序在实际消息中验证了支持证据及适用条件。
- `F`：在声明支持的输入格式/表达范围内，程序可以确定没有满足要求的证据，或值/条件明确不匹配。
- `U`：表达无法解析、适用前提未决、出现未支持的等价形式，或基准不完整。

AND遇F为F，全部T才为T，其他为U；OR遇T为T，全部F才为F，其他为U。能复核的确定性推导等同T，需保存推导记录。

不同路径的表、年份和事实不能拼成一条实际上不可执行的混合路径。部分维度各自达到100%，不保证存在完整的同一合法路径。

### 2.3 事实的结构化与匹配

建议规范形式为：

`(主体/概念, 属性, 运算符, 值, 单位, 适用条件, 时间/粒度, 来源)`。

例如`超大规模医院—bed_count—>=—2000—张`与`大型医院—bed_count—>=—1500—张`属于不同概念，不能只因数值不同就判同一事实冲突。

| 信息 | 程序匹配方式 |
| --- | --- |
| 表、字段、类型 | 限定名解析、原始目录校验、明确的别名绑定及兼容规则 |
| 比较条件 | 解析为属性/比较符/常数；`>`与`>=`严格区分 |
| 单位 | 使用原文明示的单位和经核定换算关系；不知道单位时记U |
| 公式 | 解析为表达式树，仅采用有类型、NULL和除零前提保障的规范化规则；不宣称解决任意SQL等价 |
| 坐标、范围 | 核对坐标系、轴顺序、数值及原文精度约定；容差预先登记，不能见到预测后放宽 |
| 空间几何 | 在支持的几何类型与坐标系内验证几何等价；不以“坐标相近”代替范围等价 |
| 案例支持 | 除表达外核对概念、年度、业务对象和适用前提；案例来源必须经原始资料核验 |

未出现某知识ID、SQL字符串不同、embedding分低，都不能单独证明事实缺失。程序无法核验的新表达应记U，交给复核扩展通用规则，不写本题ID例外。

## 3. A类：工程完整性与可复核性

以下分母中的“记录/片段/事实”都以去重后的稳定ID或固定切分规则定义；不能通过拆成更多容易通过的小项抬高结果。

| ID | 指标及方向 | 计算方式 | 设计思路 |
| --- | --- | --- | --- |
| A1 | 请求一致率 ↑ | `与发送边界记录的messages及生成参数一致的题数 / 有真实请求记录的题数` | 确认评价的是实际输入；另报真实请求可用数/N |
| A2 | 知识索引完整率 ↑ | `在索引中ID及原文均匹配的原始知识数 / 原始知识总数` | 区分源文件存在与索引漏入；不等于可检索率 |
| A3 | 提示词来源保真率 ↑ | `与原始来源一致的提示词证据条目数 / 具有已核定来源的证据条目数` | 原文知识逐ID比较；结构化投影按声明字段核对，不把合法转义视为改写 |
| A4 | Schema事实有效率 ↑ | `与原始目录一致的结构断言数 / 提示词中可核验的结构断言数` | 断言为字段名、类型、约束等；不把合法但无关的表算错误 |
| A5 | 来源可追踪率 ↑ | `能定位到真实来源且哈希/位置/引文核验通过的证据数 / 提示词证据数` | 仅有source_id但不存在对应来源或引文不算可追踪 |
| A6 | 运行可复现率 ↑ | `相同输入/配置重复运行中，输出与冻结基准规范化结果相同的次数 / 重复次数` | 忽略预先声明的运行时间等非内容字段；一致性高不代表语义正确 |
| A7 | 证据解析覆盖率 ↑ | `完整解析且可核对的证据块数 / 实际证据块数`，按Schema/知识/案例分别报告 | 原子指标只覆盖已支持的表达范围；未解析块不能默认为没有错误 |

工程事实核验中解析失败项单列，不能从分母悄悄移除；同时输出确定有效比例下界及“有效＋未知”的上界。A类不判断原始资料是否符合现实世界，也不能据此证明知识业务正确。

## 4. B类之一：结构覆盖

对已核定的一条路径h，令`Xq,h`是所需结构集合，`PXq`是提示词明确提供且有效的对应集合：

`RecallX(q,h) = |Xq,h ∩ PXq| / |Xq,h|`。

`CompleteX(q,h) = I(Xq,h ⊆ PXq)`。

| ID | 指标及方向 | X的定义 | 用途 |
| --- | --- | --- | --- |
| B1 | 系统召回率/完整率 ↑ | MYSQL、PG、ES等系统 | 检查联邦所需系统是否齐全 |
| B2 | 业务库召回率/完整率 ↑ | 引擎＋业务命名空间 | 不以系统正确代替业务库正确 |
| B3 | 表召回率/完整率 ↑ | 稳定table_id | 定位主表、字典表或跨年度表遗漏 |
| B4 | 必要字段召回率/完整率 ↑ | table_id＋column；必要时含类型、单位等断言 | 有表名不等于提供了所需字段含义 |
| B5 | 必要关系召回率/完整率 ↑ | 两端对象、键对应及必要关系语义 | 检查连接依据；不要求提供所有声明外键 |

每项提供宏平均`mean_q RecallX(q)`、微平均`sum命中/sum所需`和完整率`sum CompleteX/题数`。一题缺一张关键表也属于不完整，不能被其他题大量单表命中抵消。

多路径的结构微平均只能在事先冻结的可比路径上计算；不能每个版本挑选不同、分母更小的路径抬高微平均。维度最优值及联合存在性分别报告。

多路径时，逐路径保存结果；单维最优覆盖可报告`max_h RecallX(q,h)`，必须注明它只是该维度最优值。联合结构完整率B6为：

`StructuralCompleteRate = sum_q I(存在同一h，所需全部结构事实均被支持) / |Q0|`。

“参考SQL严格DDL覆盖”另用参考解析出的集合和实际candidate_tables计算，案例提及表不计DDL已提供。它是可快速运行的辅助指标，不代替B6；参考有误或有合法替代路径时，需要显示差异。

## 5. B类之二：知识记录排序与链路损失

### 5.1 检索排序

令`Lq,k`为某阶段前k条知识，按knowledge_id去重；`Gq`仅含已核定正例。先输出基准正例数和相关性标注覆盖，Gq为空的题记NA。

| ID | 指标及方向 | 计算方式 | 适用边界 |
| --- | --- | --- | --- |
| K1 | 已知正例Recall@k ↑ | `\|Gq ∩ Lq,k\| / \|Gq\|` | 基准不完整时称“已知正例召回”，不能称全量必要知识召回 |
| K2 | 已标注Precision@k ↑ | `TP / (TP+FP)` | TP/FP必须来自核定标签，未标注记U，不当FP |
| K3 | 排序标注覆盖率 ↑ | `(TP+FP)/m`，`m=实际返回条数≤k` | K2必须同时展示K3，防止只评容易的少量候选 |
| K4 | 全返回精确率区间 ◇ | `[TP/m, (TP+U)/m]` | 表示未标注候选造成的不确定范围；m=0记NA并单列空返回 |
| K5 | MRR@k ↑ | `mean_q(1/第一个核定正例的名次)`，前k无已知正例取0 | 正例不完整时只能称已知正例MRR |
| K6 | nDCG@k ↑ | `DCG/IDCG`；`DCG=sum_i (2^rel_i-1)/log2(i+1)` | 相关性等级和可用相关候选需充分标注；IDCG=0记NA，不能将未知直接设0 |

知识记录指标衡量排序过程。必要事实可能由案例或Schema提供，所以K1不等于最终提示词事实覆盖；knowledge字段非空率只作运行诊断，不进入主质量分。

nDCG的相关性等级建议预先固定为0=已核定不相关/不适用，1=相关背景，2=能正确支持至少一项必须事实。相关性与内容错误/冲突标签分别保存，一条部分有用的知识仍可能含有害片段。Gq的正例定义也需固定为相关或必须支持其中一种，不能比较时切换。

### 5.2 分阶段损失

建议保存：原始可用→索引→范围筛选→各路候选→多路合并→精排选入→预算后实际发送。对某条只有删除、没有新增的相邻边，令上游为`Sprev`、下游为`Snext`：

`StageRecall_s = |Gq ∩ Sq,s| / |Gq|`。

`AbsoluteLoss_s = |Gq ∩ (Sprev − Snext)| / |Gq|`。

`ConditionalDrop_s = |Gq ∩ (Sprev − Snext)| / |Gq ∩ Sprev|`。

对应诊断ID为K7范围筛选损失、K8候选/排序截断损失、K9预算裁剪损失。绝对损失采用统一分母便于比较贡献；条件丢失率说明上游已经找到后又丢掉多少。

名称匹配、案例、关联补充等可能在后面新增候选，整个链路是多路合并图，不一定单调。此时按各条边记录增减，再在合并点重算，不能将“上游召回−下游召回”一概称丢失，也不能把各边损失相加声称得到唯一原因占比。

源资料本来没有的正例单列为来源缺失，不记作检索漏失。最后必须回到完整消息重算事实支持，避免某条知识ID丢失但同一事实已有案例支持时误判。

## 6. B类之三：必要事实与可回答性，作为主指标

Fq只统计本题必须业务事实，不按重复出现次数计数。结构事实按Hq验证。对同一路径h记：

- `t(q,h)`：业务事实支持状态为T的数量。
- `u(q,h)`：业务事实支持状态为U的数量。
- `c(q,h)`：影响此路径需求、且优先级无法裁决的关键冲突数。

当Fq非空时：

`FactRecallLower_q = max_h t(q,h)/|Fq|`。

`FactRecallUpper_q = max_h [t(q,h)+u(q,h)]/|Fq|`。

| ID | 指标及方向 | 计算方式 | 设计思路 |
| --- | --- | --- | --- |
| F1 | 必要事实覆盖率下界 ↑ | 宏平均`mean_q FactRecallLower_q`；微平均`sum_q max_h t(q,h) / sum_q \|Fq\|` | 只认已经证实的支持；Fq固定，分母不随版本变化 |
| F2 | 必要事实覆盖率上界 ◇ | 同F1，将T替为T＋U | 展示程序或标注的不确定性，不作为已达成成绩 |
| F3 | 完整业务事实覆盖率 ↑ | `有同一路径使t(q,h)=\|Fq\|的题数 / 有必须业务事实的Q0题数` | 平均覆盖高仍可能每题缺一项；该指标还不代表无冲突 |
| F4 | 程序事实判定覆盖率 ↑ | 对已登记的路径-事实单元，`(T数+F数)/(T数+F数+U数)` | 区分质量差与匹配器能力不足，路径定义和数量跨版本固定 |

没有必须业务知识的题F1–F3记NA，但仍可依结构、任务与协议事实评价可回答性。

定义每条合法路径的可回答状态：

`a(q,h) = 全部必要结构事实T AND 全部必须业务事实T AND 任务/输出协议可确定 AND 没有关键未决冲突`。

`a_q = OR_h a(q,h)`，同样保留T/F/U。题目要求的SQL推理步骤不需要已写在提示词中；如果必要事实齐全，只因模型未推出GROUP BY或正确过滤顺序，不能把a_q直接改为F。

| ID | 指标及方向 | 计算方式 | 设计思路 |
| --- | --- | --- | --- |
| F5 | 确认可回答率 ↑ | `n(a_q=T)/\|Q0\|` | 核心指标，Q0固定；U不算通过，也不自动宣称失败 |
| F6 | 可回答率不确定上界 ◇ | `[n(T)+n(U)]/\|Q0\|` | 与F5一起展示判断范围，不当乐观成绩 |
| F7 | 全样本确认可回答占比 ↑ | `n(a_q=T)/N` | 连同源资料未决数、金标未完成数报告，防止筛掉疑难题抬高成绩 |
| F8 | 评价状态分布 ◇ | T/F/U数量及`\|Q0\|/N`、各未知原因占比 | 区分源问题、匹配未知和确定提示词缺口 |

F5/F6的上界只针对Q0内程序状态未知的情况；不能把已确认源资料无解的题自动当潜在可回答题。F5是提示词证据充分性的代理，不保证任何指定模型必然生成正确答案。

## 7. B类之四：矛盾、错误与任务版本

| ID | 指标及方向 | 计算方式 | 设计思路 |
| --- | --- | --- | --- |
| C1 | 关键未决冲突题率 ↓ | `存在影响当前需求且未被优先级裁决的关键冲突题数 / \|Q0\|` | 床位等无关坏知识不自动使其他需求不可回答；替代路径若未受影响，a_q仍可为T |
| C2 | 关键错误事实暴露率 ↓ | `包含已确认错误、且与本题必须需求相关事实的题数 / \|Q0\|` | 与缺失分开；正确证据也存在时仍记录错误干扰 |
| C3 | 已裁决冲突传达率 ↑ | `已核定优先级且实际消息清楚传达裁决的冲突数 / 需要传达裁决的已核定冲突数` | 不把system明确优先的规则和旧案例机械算作未决矛盾 |
| C4 | 任务/参考版本错配率 ◇ | `参考或训练监督违反当前冻结任务约定的核定题数 / 已核对参考的题数` | 例如ROUND2新规则与ROUND4旧监督，属于契约错配，不直接归为提示词缺证据 |

程序只在概念、主体、时间、前提、单位及定义角色可对齐时比较。两个数值不同不自动构成冲突；两条筛选条件可以同时成立，也不一定是不同定义的等价表达。规则适用性或冲突是否成立无法验证时记U，并报告冲突检查覆盖率。

## 8. B类之五：相关性、噪声与重复

按固定规则将证据token划成互斥类别：必要支持R、相关背景B、无关I、有害H、未知U。有害H可细分确定错误、过期范围、未决矛盾干扰；不确定真假的矛盾不冒充“已确认错误”。一个token只计一个主类，细分标签可以另存。

`TE = TR+TB+TI+TH+TU`。

TE包括实际发送的Schema、knowledge、案例、关系和相关检索元数据/包装，不含system指令及问题本身。每块token成本另列；不能用更长system稀释证据噪声。

| ID | 指标及方向 | 计算方式 | 设计思路 |
| --- | --- | --- | --- |
| N1 | 已确认有用证据密度 ↑ | `(TR+TB)/TE` | 背景与必要证据分开列，保留完整DDL不必然是噪声 |
| N2 | 已确认无关密度 ↓ | `TI/TE` | 不能把旧来源ID、未被参考使用的表直接标I |
| N3 | 已确认有害密度 ↓ | `TH/TE`，其中确定错误token另列 | 区分无关内容与可能误导本题的内容 |
| N4 | 噪声区间 ◇ | `[(TI+TH)/TE, (TI+TH+TU)/TE]` | 不把未审查内容当相关，也不直接判为噪声 |
| N5 | 证据标注覆盖率 ↑ | `1−TU/TE` | N1–N4必须配套展示，低覆盖时不能给精确噪声率 |
| N6 | 精确重复token率 ↓ | 对精确重复组g，`sum_g (ng−1)·Tg / TE` | 使用稳定内容切分/序列化；相似文本不直接判重复，主题相同但阈值不同不能去重 |
| N7 | 检索元数据占用 ◇ | `Tmetadata/Tinput`，另给原始token数 | 衡量分数、排序日志等占用，是否有用仍需事实或对照验证 |

精确重复率N6不需要语义标注，可直接计算；N1–N5需要核定标签或可验证的相关性规则。多条证据支持同一事实，不增加F1分子，但可能增加稳定性，不把全部重复支持都自动判为有害。

## 9. 成本、预算与效率

| ID | 指标及方向 | 计算方式 | 设计思路 |
| --- | --- | --- | --- |
| P1 | 输入长度 ◇ | `Tinput`的P50/P95/最大值，分块列出 | 固定分词器和消息格式；无法精确复现生成端分词时标为估算 |
| P2 | 超预算率 ↓ | `n(Tinput>Tavailable)/N`；`Tavailable=上下文上限−输出预留−本轮协议要求的其他预留` | 对实际这次请求计预算，不随意重复扣除未使用的未来修复空间 |
| P3 | 必要事实裁剪损失 ↓ | 在预算前→发送后这条边，按K9同样方法计算事实支持的丢失比例 | 需要重算事实，删除重复知识但案例仍支持时不算事实丢失 |
| P4 | 单位证据成本的有效事实 ↑ | `1000·已确认支持的去重必须事实数 / TE` | 表示每千token支持多少事实；只在相同题、相同基准下比较，不能替代完整率 |
| P5 | 检索/重排耗时与工作量 ◇ | P50/P95耗时、候选数、重排文档对数、缓存命中数 | 在相同硬件、模型与缓存条件下比较；区分首次加载与稳定运行 |

分块长度需要从同一次完整编码分配token位置；不要各块独立编码再相加并声称与生成端精确计费一致。无法得到精确聊天模板/分词时，报告固定代理分词器统计和误差边界，不伪造精确值。

事实裁剪损失只将T→F记为确定丢失，T→U单列为无法继续确认，不混入确定损失。

## 10. 多库与联邦的专用指标

按互斥主分组报告所有主指标：同业务库单表、同业务库多表、同系统跨业务库、跨系统联邦。联邦优先归组；题型、引擎和空间题另作交叉统计。

| ID | 指标及方向 | 计算方式 | 设计思路 |
| --- | --- | --- | --- |
| M1 | 同系统跨库结构完整率 ↑ | `跨库子集中B6通过数 / 该组可评价题数` | 主表齐全不能掩盖common字典、另一年度库缺失 |
| M2 | 跨库关系完整率 ↑ | `存在同一路径使所有跨库必需关系有依据的题数 / 该组可评价题数` | 核对键、粒度和类型/单位，不只看两表都出现 |
| M3 | 联邦接口事实覆盖率 ↑ | `已支持的必须接口事实数 / 必须接口事实数` | 接口包括输出标识、接收字段、类型/单位、去重与必要粒度约束 |
| M4 | 联邦完整支持率 ↑ | `存在同一合法分步路径，结构、接口及必须业务事实全部支持且无关键冲突的题数 / 联邦可评价题数` | 允许等价步骤顺序，不强制照搬参考的系统先后顺序 |

接口事实中不要求提示词提前写出最终SQL步骤；任务协议明确result的含义、所需标识和结构约束齐全，通用分步规划仍由生成器完成。

当前100题无SQLite、跨系统题仅9题，报告真实分子/分母。业务类型比例若来自近似标注必须注明；不能拿总体均值掩盖少数联邦题失败。

## 11. 版本比较与可选端到端验证

### 11.1 纯程序配对比较

对固定Q0，`Pass_old/Pass_new`为a_q确定为T的题集：

`ΔAnswerable = (|Pass_new|−|Pass_old|)/|Q0|`。

`Gain = |Pass_new − Pass_old|`，`Loss = |Pass_old − Pass_new|`。

同时报告T/F/U的3×3转移表。U→T是判断得到确认，未必说明原来实际不可回答；T→U是无法继续确认，也不能直接当已证明退化。额外单列确定F→T改善和T→F退化。

事实层的确定救回率：`旧F新T的必须事实数 / 旧F的必须事实数`；确定退化率：`旧T新F数 / 旧T数`，仅比较相同题、事实与路径绑定。source或金标变更时应新建版本并重新评价旧提示词，不能与旧分数直接相减。

版本比较指标编号：V1为ΔAnswerable，V2为T/F/U转移及确定改善/退化数，V3为事实确定救回/退化率。

质量比较同时展示ΔF5、ΔC1、ΔN4及Δtoken/耗时。建议按“硬性工程检查通过→可回答率及关键冲突→噪声和成本”分层评估。没有业务依据时不设任意100分加权总分；若确需综合分，应提前冻结权重，并保留原始指标与硬失败项。

### 11.2 可选查询执行指标

有已核定的参考结果和数据库时：

`ResultEq = 等价执行结果的题数 / 固定可执行评价题数`。

保留行重复数，只在题目要求排序时比较行序；字段对应、数值容差、NULL和单位规则提前确定。空结果也可能正确，非空不等于正确。联邦须真实处理步骤结果与result绑定。

执行环境失败、题意未决、未执行单列；未知执行状态同样给确认比例及不确定范围，不通过临时移除失败题抬高成绩。当前数据上结果等价不能证明所有数据库状态都等价，也不能单独证明提示词证据充分。

还可报告`提示词确认可答子集中的生成正确率`；它观察生成器如何利用充分输入，不等于模型固有能力分数。固定模型的补齐/去噪/消冲突对照建议各重复3次，按每题成功比例比较，不挑成功的一次。静态语义审查不得命名为执行准确率。

端到端指标编号：Z1为当前数据上的ResultEq，Z2为确认可回答子集的生成正确率。Z2的分子是该子集中经执行确认正确的题数，分母是同一固定子集的可执行题数，未知执行状态单列；若用于模型对比，需要使用同一提示词和同一子集。

## 12. 演算示例与建议首批报告

假设某题有4项必须业务事实：床位≥2000、年门诊量≥600万、护士≥2000、床位/护士≤1.2。经核定，当前案例已正确支持后两项，前两项缺失；结构与任务协议齐全，没有关键未决冲突。此为指标演算，不是对当前2487题执行语义的新评分。

- 业务事实覆盖：`2/4=50%`，未知0，因此上下界均50%。
- 完整业务事实：未通过；确认可回答：未通过。
- 如果两条定义知识ID均没进入knowledge块，ID召回可为0，但业务事实覆盖不是0。
- 补齐前两项且原文适用、无新增关键冲突后，覆盖为`4/4=100%`、完整支持通过；生成SQL能否正确仍要另测。

另假设100题中Q0有90题，程序判T=70、F=15、U=5，另外10题原始口径/基准未决：

- 确认可回答率F5：`70/90=77.78%`。
- 可回答率不确定上界F6：`75/90=83.33%`。
- 全样本确认占比F7：`70/100=70%`。
- 固定基准覆盖：`90/100=90%`；5题匹配未知、10题源/基准未决分别列出。

如果1200个证据token中R=400、B=300、I=200、H=100、U=200：

- 已确认有用密度：`700/1200=58.33%`。
- 已确认无关密度：`200/1200=16.67%`。
- 已确认有害密度：`100/1200=8.33%`。
- 噪声区间：`300/1200=25%`至`500/1200=41.67%`。
- 标注覆盖：`1000/1200=83.33%`，不能把其余200个token都默认有用。

首批建议固定输出：A1–A5/A7、B2–B6、K1与K7–K9、F1/F3/F5–F8、C1/C2、N2–N6、P1–P3，以及M1–M4分组。MRR、nDCG等在相关性标签足够后启用。所有题保留必须事实、匹配证据和丢失阶段明细，不能只交一张平均分表。

配套[机器可读指标目录](../evaluation/prompt_quality/metrics_v1.json)定义每项指标的ID、类型、公式、依赖和解释；该目录没有评价结论，不能被生产召回读取。
