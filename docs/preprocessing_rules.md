# 预处理与 table–knowledge 关联规范

用户最新要求：当前 LLM 独立标注配合人工审核形成的 table–knowledge 结果，作为预处理关联的理想基准。最新算法约束是完全纯程序执行：只使用原始资料的字符匹配、正则过滤及本地统计相似度，不调用LLM、不读取人工裁定或参考标签、不人工补充业务映射。审核结果仅由独立评估入口读取。

## 输入与输出

原始输入为两份 Schema、247条知识及训练划分。72张表/索引使用稳定 table_id，保留引擎和库/Schema边界。Schema解析仍只提取原始结构，不猜测字段、主外键、单位或枚举。训练案例只来自允许的训练划分；不得读取验证答案或测试答案补写规则。训练集中未出现的字段允许依据 Schema 含义关联，以覆盖未见问题。

主结果与预处理目录统一为 `tables[].knowledge[]`，每条只保留 knowledge_id 与完整 knowledge_text。所有表均输出；每表去重、按知识ID排序，无关联时为 []。不修改知识原文，审计单独保存适用片段、双方理由、裁定来源及不采用的冲突内容。

## 基准合成与优先级

来源均在 `evaluation/table_knowledge/runs/`：

- `codex-independent-v1/frozen/`：Codex独立标注。
- `flash-independent-v1/frozen/`：Deepseek Flash独立标注。
- `comparison-v1/decisions.json`：108个裁定单元，对应156份待审报告。
- `reference-v1/`：由上述来源可重复导出的理想基准。

先校验两方冻结文件、输入与提示词版本，再确认所有分歧和待审报告已有裁定。双方肯定关联的并集作为初始集合；逐项 accept 加入、reject 删除。拒绝必须覆盖模型初始接受，包括双方一致但最终在内容报告中被用户拒绝的配对。仅有内容裁定而没有关联裁定的条目，保留既有表级关系并记录不采用片段。

用户逐项结论、用户规则、按用户规则进行的代理复核、双方一致沿用必须区分。双方一致沿用不标为“用户逐条亲审”。未选配对表示当前基准的非目标关系，不等于人工证明的永久负例。

## 评价目标中的关联与内容判定

本节记录审核基准的判定依据，供离线解释误差，不作为程序可加载的人工业务规则。

| 情况 | 新规则 |
| --- | --- |
| 明示表名、真实SQL表引用、可定位表字段 | 可支持explicit，仍需处理歧义与后续裁定 |
| 字段含义、类别、统计语境直接适用 | 可支持schema_supported，不再强制出现表名 |
| 部分片段明确适用 | 可以关联；审计限定范围，不把全文视为此表可直接执行 |
| 仅同名、主题接近或外键可达 | 仅为线索，需证据或已审核结论 |
| 表已有较多知识 | 逐项采用较严格口径，避免弱相关传播 |
| 表知识较少或为空 | 逐项放宽，可接受部分适用；仍需解释依据，不设数量门槛 |
| Codex接受、Flash未肯定 | 本次R030及后续分歧按用户规则采纳Codex；候选不算接受 |
| Schema与知识冲突 | Schema优先，保留原文与不采用片段；是否关联另判 |
| 缺失引用、编码或比较符 | 保留缺失，不凭常识补全 |

本轮具体裁定还包括类别后缀解释、F等级与挂科同义、装机语境支持能源类别关联、模糊年龄区间左闭右开。这些规则按记录的适用范围执行，不能覆盖已有明确比较符，更不能据此补齐 `sog15` 等残缺表达。

最后15项使用一次性兜底：排除同轮全部待审配对后，表若存在其他未被拒绝的关联则拒绝本项，否则接受。本轮15项均拒绝；不得扩大成所有配对的贪心补齐规则，也不得推翻此前明确接受的关联。

## 纯程序算法与评价隔离

生产入口 `build-catalog` 只加载原始 Schema、knowledge.json 和训练划分。算法不读取 evaluation、decisions.json、人工复核、旧模型描述或任何审核参考结果，也不调用网络、嵌入模型或LLM。不提供加载审核结果的预处理模式。

`data/association.py` 的计算步骤：

1. 全量解析可定位的库表名、数据库作用域表名列表、唯一table.field引用，保留跨引擎歧义，不因未知表停止扫描。
2. 从原始Schema的INSERT语句提取字典值；不编写业务同义词、代码映射或按知识ID的例外表。
3. 通过可选独立训练增强模块解析SQL字段用途与问题语境；none模式不读取训练数据，auto缺文件时退回基础模式。仅使用允许的训练划分，不使用验证或测试标签。
4. 将Schema注释、原始字典值及知识分句构建成基础字符2–4gram与英文标识符TF-IDF语料；训练问题在独立增强器中评分，不改变基础IDF。相似度是本地词法统计，不宣称具备LLM业务理解。
5. 综合显式引用、按字段稀有度加权的覆盖、注释余弦相似度、训练问题相似度、字典值精确匹配及声明外键上的字典值证据。已限定表的句子对其他表的偶然字段匹配降权；仅外键存在不产生关联。
6. 全局阈值0.30筛选；不强制每表关联。每对保存分项得分及证据，完整原文独立保留。重复执行重建关联，按ID稳定排序。

TF-IDF完全由当前原始语料拟合，没有预训练权重或标签训练。全局阈值在当前审核基准上选择，成绩属于同集开发评估，不可当作独立测试泛化成绩。人工裁定中无法由原始字符推得的取舍继续作为差异报告，不将其写成白名单。

预处理、索引与检索应使用同一版本关联。额外向量或关键词召回作为候选保留，不能自行变成确认关系。关联与内容执行分开：生成阶段需要消费Schema优先和冲突处理记录，单独加载tables.json不能证明内容冲突已修复。

## 验收与版本

逐表比较知识ID集合并核对完整原文，报告命中、漏关联、多关联、空表分布和依据分类差异。汇总micro precision、recall、F1：precision=命中/程序关联，recall=命中/基准关联；分母为零时记未定义并报告计数。不得用大量未关联配对形成的accuracy掩盖漏关联。

当前目标是与基准完全一致，所有差异逐项解释，不另设未经用户确认的容差。基准的结果不能替代对未见数据泛化能力的评估。输入、策略或裁定变化后创建新版本，保留旧版、来源哈希和审计。

## 当前实现和复现

`data/catalog.py` 已调用新纯程序关联器；`retrieval/index.py` 不再独立按字段同名或另一套正则补关联，目录关联是唯一来源。当前索引版本为4，问题/文档编码隔离及精排流程见[混合检索方案](hybrid_recall.md)，旧索引需重建。精排只影响查询时的候选排序，不参与纯程序预处理或新增关联。Schema主外键和字段注释保留原始内容，不用知识推断替换描述。

```bash
PYTHONPATH=src .venv/bin/python -B -m text2query.cli split-dataset
PYTHONPATH=src .venv/bin/python -B -m text2query.cli build-catalog
.venv/bin/python -B evaluation/table_knowledge/evaluate_preprocessing.py --output-dir /tmp/table-knowledge-eval-new
```

前两步生成本地划分及预处理目录（已有划分不覆盖）。第三步独立读取基准评估；使用临时训练划分，不修改工作目录中的划分，也不把基准传给关联器。详见 `evaluation/table_knowledge/runs/programmatic-v2/README.md`。

训练模块拆分前实测：输出256对，命中200对，多关联56对、漏关联70对；precision=78.125%、recall=74.074%、F1=76.046%。这是一个可复现的纯程序近似，尚未完全复现人工基准。

## BM25实验版本

构建命令支持 `--association-method bm25`、`--association-threshold`、`--bm25-k1` 和 `--bm25-b`。默认保持TF-IDF。BM25只替换Schema/训练问题与知识之间的文本评分，其他匹配规则不变，不读取答案。

BM25采用正IDF及词频饱和、文档长度归一化；文档为知识全文及分句，查询为Schema描述和训练问题。使用查询IDF理论上界（包含未见词）将分数缩放到0–1，取最高分，不将分数解释为概率。

相同输入、划分与答案下，默认k1=1.5、b=0.75、阈值0.30得到305对关联：命中186、多关联119、漏84，F1=64.70%。答案非空表完全覆盖25/44=56.82%，全部表53/72=73.61%。覆盖略高而精度低于TF-IDF，暂不切换默认。阈值取舍及复现命令见[对照报告](../evaluation/table_knowledge/runs/bm25-v1-default/COMPARISON.md)。

## 噪声约束与提示词传递

用户要求不以极端调整阈值换取覆盖；离线评价按无关关联数/有效关联数目标不超过200%。有效为程序与答案交集，无关为程序比答案多出的配对。整体与逐表均报告，零有效但有无关项不能视为达标。当前两版的逐表统计见各自 `noise_audit.json`；整体达标不代表逐表达标。

这些是table–knowledge配对口径，不能直接当成某个question最终提示词的无关比例。按文本字数或token计量时还应另行统计，不能用条数替代token预算。

常规规划/生成流程通过ContextBuilder按候选表和当前问题检索knowledge，默认最多12条，预算不足时整条移除；保留条目的knowledge_text原文经JSON序列化放入user消息，不自动摘要、改写或只提取适用片段。table.knowledge用于建立检索归属，不将所有表内知识全量拼入提示词。关联审计及完整冲突记录不会自动附加到knowledge条目。

微调生成入口 `submission/finetuned.py` 的build_instruction只拼Schema/DDL或mapping，不直接拼knowledge；knowledge可通过检索间接影响选表。上述结论基于代码和离线提示构造检查，不涉及实际LLM调用。

## 原始描述补采修复

`catalog.py` 现支持缺少正式COMMENT时采集紧邻CREATE TABLE的单行 `--` 注释；只可跨过当前表自己的DROP语句，不越过USE、其他SQL或段落分隔线，正式COMMENT优先。编号与说明原文保留，不将旧年份描述复制到其他库。

ES在解析JSON前保留 `//` 注释位置，保留字符串中的URL和双斜杠。只对完整单行属性且名称、mapping唯一匹配的字段补描述；歧义或多行说明留在原文中，不随意指派。每条新增描述通过description_source记录来源文件、原始行号和引文。

本次恰好补回16个表描述和7个ES字段描述。现有TF-IDF及BM25目录只刷新描述、描述统计和Schema文档，保留既有knowledge关联、评分审计及其余目录字段。修复核验记录见 `evaluation/table_knowledge/schema_description_fix.json`；此前的缺漏审计是修复前快照。

修复后有描述的表为63/72，字段为337/456；其余源头缺失内容和ES段落标题未补写。后续完整重跑build-catalog时，新增描述自然会参与关联评分，旧的答案对照报告仍是修复前版本，不应当作重跑后的成绩。

实现须遵守[社区库复用原则](library_reuse.md)：BM25核心交由rank-bm25，正IDF及归一化仅作为兼容适配；JSON对象边界使用标准JSONDecoder。为保留注释位置所需的扫描、来源关联和项目匹配策略保留为小型适配层，不另写通用解析器。
