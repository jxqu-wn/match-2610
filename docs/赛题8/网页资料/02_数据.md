## 一、数据简介
本赛题要求参赛队伍基于数据库和知识库，通过构建智能体、工作流等智能化技术方法，利用大模型实现自然语言转化为数据查询语言。赛题数据集主要包含数据库、知识库及相应的问答对。其中数据库包含MySQL、PostgreSQL、Elasticsearch和SQLite四种数据库系统，均有可被查询的模拟数据；知识库包含字段注释、计算公式、业务知识、通用知识等，采取条目式的方式进行存储；问答对包含问题id、问题和查询指令。

## 二、数据说明

### 1. 数据集构建方式

1. **自主构建的核心数据集**：主要选取电商、教育、金融、交通等领域，参照Text-to-SQL经典数据集（Spider、BIRD等）和互联网公开数据进行数据库、知识库和问答对构建，参考相关公开文献资料进行数据库字段设计。数据库中通过人工编写、模型算法批量生成等方式构建模拟数据，确保所有查询指令均有执行结果，知识库通过人工编写和模型生成的方式进行构建，所有数据均为虚拟内容，不具备真实性和实用价值。
2. **改造翻译的开源数据集**：选取Text-to-SQL经典数据集BIRD中23个数据库及对应的问答对，进行问题翻译改写、数据分类标注、知识库抽取构建、脏数据筛选清洗等操作，形成符合本赛题特点的数据集，能够考察模型对通用查询指令的生成能力，同时增加数据源类型和数据库数量，提高模型自主进行数据库路由的难度。

*注：数据库文件不向参赛队伍提供，主要用于支撑评价函数的执行。*

### 2. 初赛数据集文件清单

| 文件                     | 文件名                | 文件说明                                                                                                         |
| :----------------------- | :-------------------- | :--------------------------------------------------------------------------------------------------------------- |
| **核心数据库模式** | `Core_Schema.txt`   | 包含自主构建的核心数据库模式项信息（如表名、列名、外键等），不包含数据库的值。                                   |
| **通用数据库模式** | `Common_Schema.txt` | 包含自主构建的通用数据库模式项信息（如表名、列名、外键等），所有字典表均有数据插入语句。                         |
| **BIRD数据库模式** | `BIRD_Schema.txt`   | 包含改造BIRD数据库模式项信息（如表名、列名、外键等），不包含数据库的值。                                         |
| **知识库**         | `Knowledge.json`    | 包含1800条知识，每条内容为：知识编号（knowledge_id）、知识文本（knowledge_text）。                               |
| **初赛训练集**     | `QA_train.json`     | 共5830条问答对，每条内容为：问题编号（question_id）、问题文本（question）、目标数据源（db）、查询指令（query）。 |
| **初赛测试集**     | `QA_test.json`      | 共400条问答对，不提供数据源和答案，每条内容为：问题编号（question_id）、问题文本（question）。                   |

*说明：涉及跨数据源查询时，问答对中的数据源和查询指令分别有两个值：`db1`、`db2`、`query1`、`query2`。*

### 1、数据库说明
本赛题的数据源包含MySQL、PostgreSQL、Elasticsearch和SQLite四种数据库系统
其中BIRD数据集改造的问答对，其对应数据均在SQLite中
通用数据库Common的数据全部存储于MySQL
医疗库存储于Elasticsearch
船舶库存储于PostgreSQL
其他领域数据存储于MySQL
请参赛队伍在构建解决方案时注意查询指令方言特性。
**备注：** 在Elasticsearch、PostgreSQL中仅包含一个库，可以查询指令可以直接对表名进行查询，SQLite和MySQL中包含多个数据库，查询指令中要以库名.表名的形式进行查询。
**备注：**  通用数据库Common中的行政区划表和字典表，参赛队伍可以将其视为知识，允许进行重构，以其他形式存储查询。字典表全部数据在commom_schema中，行政区划表数据在administrative_division.sql中。
### 2、行政区划表开放下载
administrative_division是common库下的行政区划表，现在将数据开放给所有参赛队伍，数据包含初赛中用到的行政区划信息。
参赛队伍可以将其视为知识其进行重构，改造为更加适合大模型检索匹配的形式存储,也可以当做字典表进行关联查询。
**注：** 表中数据未必全部符合现实情况，请参赛选手构建解决方案时让大模型以该表数据为准，而不是利用模型本身的常识。
