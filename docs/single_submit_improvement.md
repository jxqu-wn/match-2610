上述 SQLite 目标是原始 BIRD 来源 SQL，**不是网站隐藏答案**。旧文件与其生成来源完全匹配属于预期现象，不能据此声称网站 SQLite 准确率为 100%。原网站旧文件得分率为 91.21%。本地执行保留重复行，并在来源查询明确要求排序时比较顺序；浮点统一保留八位小数。

当前 1016 有 3 道本应属于业务库的问题被生成为 SQLite；其 117 条联邦查询均已有直接 `IN (result)`。因此，新文件问题不能沿用旧文件“未实现两步协议”的单一解释。它与 AI 文件存在 8 道系统集合差异，但 AI 本身不是逐题金标，差异只能触发诊断。

初版结构检查之外还确认了 `ST_Within(geography, geography)` 的无效签名，现已增加检查。它只支持 geometry；`ST_Intersects` 与 `ST_DWithin` 有 geography 重载，不能一概拒绝 geography。
依据：[PostGIS ST_Within](https://postgis.net/docs/ST_Within.html)、[ST_Intersects](https://postgis.net/docs/ST_Intersects.html)。

1016 单步 MySQL 查询中仅 23 条出现 `ROUND`，AI 为 77 条。平均值的中间计算不必都取整，因此此计数只是口径落实的诊断，不能直接当错误数。训练 SQL 本身也有精度冲突，需要把“遵守当前口径”和“与旧参考等价”分别记录。

## 本轮实现与边界

- `submission/integrity.py` 复用 SQLGlot Schema qualification，补充未限定/歧义/派生字段、同层嵌套聚合与窗口聚合检查，以及两步单键值列表协议。校验不证明业务正确。
- `submission/evidence.py` 保留原始字段、原始字典行与 knowledge 原文。外键只生成候选；显式声明其他业务库的知识不迁移到本轮 72 张业务表。1833 条知识中保留 280 条，排除 1553 条外库声明，逐条记录原因，未按 ID 配置规则。
- `submission/grounded.py` 将规划、初稿和复核分开；修复重新提供完整当前证据，不累积历史消息。真实但未提供过的表须先补给模型再生成，不能仅因全目录校验通过就接受。
- `evaluation/submission_quality/` 包含只读三文件诊断、真实 BIRD 执行、隔离 MariaDB 空库编译、GPU 召回与开发/验收编排。
- Flash 可显式开启思考模式，已用不含业务资料的探针确认。文档依据：[DeepSeek thinking mode](https://api-docs.deepseek.com/guides/thinking_mode)。

## 实验约束

60 道开发题与 48 道本轮验收题在生成前冻结；按单表、同业务多表、同系统跨业务库、跨系统分层，验收题不用来调参。全部来源于此前已研究过的 284 题，故不是全新独立测试集。训练索引排除这些验证题的参考答案。

使用指定 SSH GPU 上的 Qwen3 Embedding/Reranker 0.6B、BM25 各 50、RRF 常数 60，重排 50 个候选。108 道题在前 8 张 Schema 候选中均覆盖参考所需表；这是**规划和预算裁剪前的候选覆盖率**，最终提示词需再次核验，不能混淆。

首轮 12 道开发题的结构/编译检查：直接非思考 8/12；直接思考 12/12；先规划思考 11/12（1 题输出 token 耗尽）。这些数值不是语义准确率。人工检查已发现统计总体、学期对象、知识条件适用性、输出形状等问题，仍需迭代。

生成器不读取 `result_ai.json`、`result_1016.json` 或验证参考 SQL。用户已授权本轮 108 题生成与独立参考可见评分；参考答案只进入评分请求。LLM 语义评审不等于实际业务库执行准确率。没有逐题网站明细与实际业务数据，无法提前承诺达到 89.07% 的正式得分。

在开发、验收、格式和来源检查完成前，不运行完整正式题集、不覆盖 `result.json`，也不使用唯一网站验证机会。

## 开发中发现的证据丢失

第五轮高思考配置完成 60 题，58 题通过结构与编译检查。两个失败分别是知识不足与 ES JSON 多次格式错误。该轮仅完成 59 题的独立语义评分时，52 题被判符合题意、3 题错误、2 题有歧义、2 题生成失败。它是开发诊断，不是验收成绩。

确认存在两种流程缺陷：

- 知识候选齐全，但规划提示词按“简单题”6k 预算裁剪，税务问题的净利润特殊定义、税率规则落在裁剪部分。不能把这种资料缺失归因于原始知识没有公式。
- 规划要求模型逐字复制引文，标点变化、拼接、省略号及非连续的问题触发词会校验失败。旧实现静默丢弃这些知识，在五道开发题中出现。完整候选召回率不能证明实际知识到达率。

第六轮改为程序切分知识原文并分配稳定片段编号，模型选择编号，程序直接提取原文；非法编号或触发词进入有界计划修复。知识原文、ID 不变，不进行模糊改写。复杂规划预算上限 12k，其余 10k；生成/复核按复杂度使用 6k 或最多 16k。先移除案例及冗余元数据，再裁剪低排名知识，记录实际删减项。模型请求已有表的补充证据时，允许从冻结知识候选重新补充定义，避免将缺知识误判成缺 Schema。

输入预算扩大已获用户许可。这里的 LLM 证据适用性判断属于 SQL 生成编排，原始预处理、原文切片、关联与候选检索仍由程序完成；没有把验证参考 SQL 或人工审核结论写入生产映射。

严格结果等价另行报告。典型差异包括城市代码与名称、实体编号与“编号+名称”、全部字段与实体简表、年度期末与年内最近一期，以及比率保留两位与旧参考保留四位。这些差异可能影响结果集判题，不能因为语义评分认为“合理”就忽略。

## 最终候选实现 v11

前述预算描述是开发中间版本；最终候选恢复简单题所有生成阶段的估算输入上限 6k。规划使用专用精简指令，不携带 SQL 生成专用的大段说明。题意明确涉及跨年、指标、空间等复杂要求时规划最多 12k；检索候选混入其他系统不构成扩窗理由。实际需要多表/多库或复杂运算的生成和复核最多 16k。两类预算均包括 system、规则和 user 输入，不只计算 Schema。使用 Qwen tokenizer 加安全余量估算，并记录 DeepSeek 返回的真实 prompt_tokens；不是 DeepSeek 官方 tokenizer 的硬证明。

v10 初步验收曾运行生成，但未进行语义评分。开发题 1396 的预算记录暴露“无关系统候选触发简单题扩窗”问题后，使用开发证据修正为 v11，并重新冻结配置。旧记录完整保留，原因见 `outputs/experiments/single-submit-v1/budget_protocol_amendment.json`；没有根据验收 SQL 或参考答案调参。

补充的程序证据包括：

- 直接从原始训练 SQL 抽取非聚合输出维度、GROUP BY 和简单排序列，保留训练题目、来源、弱证据标记。不会拷贝筛选值或指标公式。完整训练 SQL 仍最多两例，独立复核只看到紧凑使用证据。
- 使用全部六个 BM25 案例候选，避免仅因前两例不兼容就漏掉后面的同任务案例；紧凑证据最多六例，预算不足时优先删减冗余项。
- 在冻结知识候选中，按原文定义标题与已选知识中实际提及的同一概念，提取一跳定义依赖候选。例如分类分支引用某类别时，提供该类别原有判定条件。它仍是待核对候选，不升级为确认关联，不改知识原文，不使用 ID 或验证答案规则。
- 复核请求真实目录表 ID 时，即使模型把 ID 放在 reason 中，程序也可提供其完整 Schema；补充计划新增的真实表实际加入上下文，不再只记录计划。

结构与编译已通过、全部可用 Schema 和知识也已补给，但复核仍索要不存在的业务值样本时，保留此前通过结构/编译的候选，明确标记 `unresolved_source_evidence` 并保留复核原文。该状态**不表示语义复核通过**，在报告中单列，不能混入“确定正确”。没有合法候选时仍失败，不补造取值。

失败案例在同一冻结任务内可恢复：保留失败轨迹，添加请求重试编号避免反复命中相同的错误缓存；已成功题不重新生成。完整正式任务的计数始终为一次，恢复不另起配置或完整任务。

本轮入口是 `evaluation/submission_quality/experiment.py`（开发与独立验收）及 `final_run.py`（一次冻结的正式任务）。实际生成器位于 `src/text2query/submission/grounded.py`；没有将本轮验证参考加载进生产模块。`final_run` 的 readiness 是程序内部冻结证书，不是额外用户审批流程。

## 冻结后的验证结论

v11 开发 60 题、验收 48 题均生成成功并通过结构/字段校验和 MySQL 步骤编译。最终实际提示词完整表及业务库覆盖为开发 60/60、验收 46/48；同系统跨业务库合计 18/18、跨系统合计 9/9 均完整覆盖。43 项相关回归测试通过，108 题的估算和 API 实际输入 token 均未超出各次请求的预算。

独立 Flash 语义评审：开发 48 符合、4 错误、8 歧义；验收 42 符合、1 错误、5 歧义。验收 MySQL 33 题中 29 符合、4 歧义，没有明确错误；同系统跨业务库为 7 符合、1 歧义，跨系统为 3 符合、1 空间边界歧义。结果等价统计另见自动生成的 `docs/single_submit_results.md`，不能把“符合题意”当成“与参考执行结果严格相同”。

验收缺表的两题分别只写“学期编号为1”和“院系编号为4”，没有指定年份；原始参考选择 2025 库，模型按其他训练用法选择 2024 库。两套 Schema 同构但数据不同，属于原题缺少年份/默认库信息；候选阶段两年表均存在，不能解释成 embedding 没召回到这些表。也不能靠把所有年份表都塞进提示词，声称业务答案歧义已经解决。

验收唯一明确错误是 ES 平均值未落实当前两位小数规则；候选与原始参考 DSL 完全相同。正式题的 ES 使用本轮开始就冻结的历史预测，不因这项验证临时改变策略。其他歧义包括空间边界是否包含、未指定报告期、退课 NULL/成绩缺项口径。

开发残留错误集中在统计粒度和知识适用性：把多城市分别统计变成总计，把每船统计变成总计，将两年各自的 top1 变成合并后全局 top1，以及把证书类型数换成证书记录数并附加有效期过滤。这些案例的提示词已提供所需表和原始知识，不能继续归因于缺表。新的完整提示词仍无法保证 Flash 每次正确运用证据。

因此，本轮确认并修复了真实的流程问题，也保留了模型能力、原题歧义与参考冲突的独立记录。尚无正式业务数据或本轮网站分数，不能证明已达到大参数 AI 的 89.07%；正式文件保留网站唯一验证机会供后续检验。

## 正式任务中的装包修复 v12

正式任务保存 283 道业务题后，发现了此前验证集没有暴露的装包缺陷：行政区划样本同时带有原始 INSERT 和解析值，在简单题 6k 预算内挤掉了排名靠前的知识定义。例如“经济发达地区”的原始定义位于候选第 2 名，却因保留了 7 条区划样本而未进入规划提示词。此时不能把失败归因于模型不知道地区范围。

暂停后将装包优先级改为先精简冗余来源样本，保留最高匹配的原始行和一条原始字段不一致示例，再裁剪定义与知识；原始行、Schema、知识、模型及全局参数均未改写。该题规划现在保留 16 条知识，估算 5917/6000 tokens，并已生成通过结构与编译检查的查询。这个实例仅用于确认通用装包缺陷修复，没有按题号或知识 ID 添加生产规则。

修复后的 108 题同集回归全部生成成功，完整表和业务库覆盖仍为 106/108；所有 18 道同系统跨业务库与 9 道跨系统题均完整覆盖。语义评分开发集为 50 符合、2 错误、8 歧义，原验收集回归为 41 符合、2 错误、5 歧义。两次分数变化同时包含生成和评审随机性；原验收集已被查看，不能把这次回归伪装成新的独立验收。MySQL 验收子集仍为 29 符合、4 歧义、0 明确错误。439 次请求的输入估算均符合各自预算，48 项相关回归测试通过。

通过实际装包删减记录筛出 125 道受影响或失败题，旧轨迹归档到 `full/pre-packing-fix/inference/`；158 道不受影响的成功题按 SHA-256 原样保留，另外 269 道未完成题继续执行。使用 `readiness-amendment.json` 保留原始冻结证书和旧代码校验值，并固定修复代码及回归证据；没有重置正式任务或网站次数。最终结果混合了 158 道原版本成功结果和 394 道修复版本结果，逐题来源及版本在导出时记录。
