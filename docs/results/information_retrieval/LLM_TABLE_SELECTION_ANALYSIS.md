## 已得到直接证据的机制

### 需求未映射到字段及关联路径

4765 要求 1977 年，但 selected_tables 的 required_columns 没有任何日期字段，最终却 ready。参考 SQL 从 movies_total_gross.release_date 过滤；已选 characters 自身也有 release_date，因此可以确认漏了年份需求，却不能据此证明必须增加参考表。

4465 涉及某论文引用了哪些含指定词的论文，模型仅选 content；缺少 cites 的引用方向与引用目标关系。这是漏掉题目要求的关系，而非只少输出字段。

5148 把页面内第二个词的出现次数替换为 biwords 的词对 occurrences，并在 assumptions 声称需要通过 lid 关联 pages；join_plan 实际只有 biwords 到 words 的关系，没有页面限定路径。参考 SQL 使用 pages_words.pid/wid/occurrences。表名、次数字段存在并不能保证统计对象和限定路径成立。

3786 参考 SQL COUNT(DISTINCT game_publisher.game_id)，模型只选 game_platform/platform，缺少区分游戏与发行/平台记录所需的 game_id。这里不可直接把 game_publisher 判断成冗余桥表。

### 相似字段的统计口径被模型自行确定

4979/4981/4985 使用 rootbeer.PurchaseDate，舍弃 transaction.TransactionDate。4985 明确声明按购买记录条数理解日均销售。参考 SQL 基于交易日期统计。这不是交易表没被召回，而是两个日期及记录粒度的选择。

1037 明确引用训练案例1044，改用 energy_company.staff_count，参考表集合则包含 employee。既有案例可能影响口径选择，但没有反事实实验，不能断言案例一定是导致错误的原因；汇总字段与明细计数是否一致也未验证。

4571 用 Episode.votes，参考 SQL 汇总 Vote.votes。是否等价需要验证字段含义和数据，不能仅由表集合不同判错。

### 知识冲突和问题信息不足

4789 的 knowledge:712 将 revenue.Total 解释为电影总票房收入，knowledge:197 和 schema 将其解释为公司业务总收入；knowledge:706 还把年度收入表 Year 解释为上映年份。模型明确拒绝 revenue.Total，采用 movies_total_gross.total_gross。这是可观察的信息冲突，参考答案与其口径不同，不足以证明模型选择在业务上必然错误。

1622 未指定学年，模型假设最新2025，参考2024；1789 同样未指定学年，模型随案例选择2024，参考2025。没有稳定的已知年份依据，单纯强化参考一致率可能变成猜标签。

5212/5345 的 books 与 book_publishing_company 都有书籍和出版社结构。模型选后者，参考前者。若缺少出版社实体与库的明确关联或取值信息，单凭结构能回答同一问题并不能证明该库含指定出版社。当前没有值域查询工具。

4916 参考 SQL 关联 person，但年龄来自 games_competitor，年份和季节来自 games。person 是否必要需要检查关联过滤效果。3106 参考 SQL 额外关联 roysched，却取 titles.royalty；该关联可能过滤或复制记录、改变加权，不能未经数据核验就称其冗余或称模型错误。

### assumptions 隐藏了真正的缺口

3404 明确承认缺国家表、无法提供国家完整名称，却放进 assumptions，gaps 和 unresolved_gaps 留空并 ready_with_assumptions。校验仅检查缺口数组是否为空，没有判断 assumptions 是否实际表达未满足要求。

当前 evidence 校验只确认 source_id 存在，没有验证引用材料确实支持对应表、字段及口径。模型可以引用合法来源完成结构检查，同时遗漏题目要求或自行改变统计口径。

### 结构协议与修复失败会掩盖正确选表

4204/4248/1852 首轮已经选齐参考表，但 join_plan 引用包含未选端点的声明外键。修复有时增加了 left/right 字段，却保留 relation_id；validate 优先读取该 ID 对应原关系，新写端点不生效，因此仍然失败。真实外键应保留检查，问题在于模型将外键路径和本次查询关系混用、修复未遵循协议。

4317 选择 Business.name，但真实 schema 不包含此字段，修复重复原输出。这说明结构失败并非全是关系问题。

6203 首轮猜出未提供的 actor；修复删除 actor，仍保留未经验证案例关系且无假设，继续失败。结构修复并没有解决演员姓名的证据缺口。

这些错误最终输出 error，所选表集合为空，直接拉低覆盖指标。不能全部归因于 LLM 不会选择参考表。

### 额外表的目标约束不足

16 题参考表已齐仍多选。3918 按 region_id=4 求和却增加 region；1662 返回班级ID，却增加 class 并同时说明实际输出 class_id。其他行政区划/公司表可能用于名称输出或地区条件，应逐题判断。

提示词强调实体业务名称和检查字典表，没有明确要求每个选表都对应不可替代的输出、条件、聚合或连接任务。名称补充倾向与最终最小必要集合的目标可能存在张力。不能将全部额外表视作有害连接，实际 SQL 尚未生成或执行。

## 噪声与因果边界

最终上下文共有1430次候选表，372次为参考表，非参考比例73.99%。该数字是标签相对的候选冗余率，不是有害噪声比例；替代路径、实体名称、字典和桥表也可能有用。

有相近业务库、同类字段、冲突描述及相似案例竞争的直接证据。但未固定其余输入进行删除/替换证据实验，尚不能给出噪声造成了多少错误，也不能证明排序靠后必然导致漏选。

## 判断

当前主要问题是：没有可核查的“题目要求—字段—统计对象—关联路径”覆盖结果；允许假设承载未解决需求；结构修复失败使正确的表选择结果丢失；最终表集合缺少明确必要性约束。与此同时，知识冲突和问题缺少年份/实体定位信息使部分参考一致性差异无法由模型单独解决。

这些是诊断结论，不是加入业务规则的授权。本次未修改代码，未将参考答案用于检索或模型上下文。
