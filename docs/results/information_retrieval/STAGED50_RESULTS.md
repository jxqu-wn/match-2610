# 三阶段流程：同50题真实模型回归

2026-10-11。系统类型 → 业务库 → 表/字段。复用旧live50的50个问题ID及顺序，系统类型仍来自训练集拟合的embedding分类器。是诊断回归，不是重新抽取的独立泛化样本。

本轮生成开始后没有调整提示词、业务目录、索引、预算或重测失败题。配置、提示词SHA256和代码SHA256保存在run_config.json。旧版产物未覆盖。

产物目录：`outputs/information_retrieval/live50_staged_v1/`。

## 覆盖与匹配

“完整覆盖”允许额外候选；“完全一致”要求集合相同。按出现次数统计时，同一库/表在不同题中分别计数。所有失败和待澄清题保留在50题分母。

| 阶段 | 完整覆盖题数 | 集合完全一致题数 | 参考出现次数召回 |
|---|---:|---:|---:|
| 系统类型 | 50/50，100% | 50/50，100% | — |
| 业务库路由有效输出 | 41/50，82% | 39/50，78% | 46/58，79.31% |
| 最终检索上下文中的表 | 41/50，82% | 7/50，14% | 74/93，79.57% |
| LLM最终选择的表 | 39/50，78% | 35/50，70% | 71/93，76.34% |

业务库完全覆盖的41题，表上下文完全覆盖41/41，100%。上下文允许候选冗余，因此其集合完全一致率不是主要目标。初次与最终业务库覆盖均为41题；初次与最终表上下文覆盖也均为41题。

表上下文完整覆盖从旧版47/50，94%，降至41/50，82%；最终表集合一致从41/50，82%，降至35/50，70%。不能把减少候选范围解释为已提升总体效果。

本轮未重新审核完整业务语义，没有生成或执行业务SQL；字段结构完整不能证明统计口径正确。

## 成功提取时的位置/排名

业务库阶段没有检索分数或经过校准的相关性排名，目录按ID字母顺序提供，LLM直接选择。以下仅是LLM选择数组中的输出位置，不代表置信度排序：46个正确选中业务库出现次数中，40个位于第1位置、6个位于第2位置，平均1.13。

表排名重放原问题在各个已选业务库内的RRF排序。不是旧版跨系统全部业务库的排名，也不是补检索gap查询排名。只统计成功提供的74个参考表出现次数，不把19个遗漏算成高排名。

| 库内原始RRF排名 | 成功提供的参考表 |
|---|---:|
| 第1名 | 37/74，50% |
| 前3名 | 58/74，78.38% |
| 前6名 | 70/74，94.59% |
| 前8名 | 71/74，95.95% |

平均排名2.50，中位数1，P90为5，P95为8，最大12。最终被LLM选中的71个参考表平均库内排名2.48，56/71在前3，67/71在前6。

参考表在实际表上下文中的位置：平均2.47、中位数2；57/74在前3，70/74在前6，最大8。

低原始排名的表依靠关系或案例补入：4296的Attributes排名11，外键补入；3277的Team排名11，案例补入；4191的Attributes排名12，案例补入；5603的Master排名8，外键补入。相似表错误仍存在：5603参考Goalies的库内排名2，模型选GoaliesSC；正确表靠前并不能证明下游选择正确。

## 未完整覆盖的9题

| 题号 | 参考业务库 | 失败或缺口 |
|---|---|---|
| 1632 | education_2024 | 未指定年份，业务库阶段请求澄清 |
| 4516 | simpson_episodes | 目录未明确艾美奖/配音奖，业务库阶段请求澄清 |
| 3602 | professional_basketball | 目录虽有球员/球队/季后赛简介，模型认为不足以确认NBA冠军名单，提前结束于业务库阶段 |
| 4973 | beer_factory | 人名及交易业务无法由目录定位，请求澄清 |
| 1411 | ecommerce、common | reason/evidence提及两库，但选择数组仅列ecommerce，引用包含另一库导致结构检查失败，修复仍失败 |
| 5327 | books | 选为book_publishing_company，后续在错误库内查页数；只提出missing_attribute，未触发业务库重选 |
| 5487 | image_and_language | street lights未出现在目录简介中，无法定位，请求澄清 |
| 1530 | ecommerce、common | 同1411，共享字典未正式列入选择数组，引用结构修复失败 |
| 341 | finance_tax、common | 简介未明确外商投资企业覆盖，业务库阶段请求澄清 |

这是有效输出口径：1411/1530在文字解释中识别了共享字典，但没有形成通过结构检查的库集合，不能当作成功提取。1632的年份歧义是真实题面问题，评估依然按参考计为未覆盖，不据此断言模型判断错误。

另有428在正确业务库、参考表已提供的情况下，join_plan端点未全部选择，结构修复失败。这不影响其上下文覆盖，但最终选表失败。

主要问题目前前移到业务库阶段：目录只提供表名/简介/跨库外键，缺乏字段及具体业务值线索；模型也把完整查询可解性作为选择业务库的前置条件，产生过于保守的拒绝。阶段隔离便于定位，但过早硬限定范围导致召回下降。暂未针对失败题修复。

## 成本与隔离

97次真实API调用：50次业务库判断、2次业务库结构修复、43次表判断、2次表结构修复。没有业务库重选。所有97次传输成功，3个error来自输出结构验证，不是网络故障。

输入465997、输出16976、总计482973 token，约为旧版345431的1.40倍。单调用输入P95=8531、最大9527；输出最大489，无输出长度终止，无上下文裁剪。

168个不同的实际提供案例ID均来自分割后的训练集；初始及补检索上下文来源均核查，训练/验证ID重叠为0。参考SQL只在生成之后用于本地评分，不进入业务路由、检索索引或外部请求。
