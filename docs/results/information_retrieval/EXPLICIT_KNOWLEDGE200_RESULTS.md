# 明确知识关联优化：同200题真实回归

当前版本system-table-explicit-knowledge-v5。复用之前200题、相同训练分类器预测、schema/knowledge/训练子集索引、模型deepseek-flash与预算（初始8表、最多12表，知识12条、案例4条，单次总预算24000、输出预留3000）。这是固定样本回归，非新的独立泛化评估；验证参考SQL从未发送至模型。

## 变更边界

新增explicit_knowledge.py，仅按原文解析：数据库范围内明确表名、完整库.表名称、以及表与字段均存在且全catalog唯一解析的表.字段。仅字段名、歧义表.字段、无法唯一识别的库表均跳过；不采用旧知识关联的字段同名推断来提升表。未新增业务描述、术语释义、值域、统计分母或关联口径，不额外调用LLM理解业务。

1800条知识中，1519条存在可确认表引用，281条未用于新增定位链路。人工核对knowledge:24/146/247/249/1608/1615/1645/1575/17/21及117/233/234/1411/1421，共15条原文与关联，结果保存在explicit_link_audit.json。knowledge:1645（仅字段公式）和1575（enrollment.is_withdraw跨库歧义）无新增关联。
知识召回要求原文命中问题中的至少一个低频文本token（长度至少2，排除纯数字，出现于最多10%的明确关联知识文档；仅小语料测试放宽到至少1条）。这是文本过滤，不能视为业务相关性保证。取前12条合格知识，通过明确表引用投影到表，以该表命中知识中的最高RRF分数排序，作为第三通道。知识通道权重0.25，原schema的关键词/语义通道不改。重复知识不会按数量累计提升同一表。候选配额、FK扩展和训练案例补表机制不变。

原始知识句子在原知识配额内提供给模型，附带可追踪的source_id、命中文本token和原文引用方式。schema字段和描述不改写。

## 最终结论与实际实验用量

此次排序尾部有所改善、表集合完全一致增加3题，但完整参考表覆盖没有提升：最终上下文少覆盖2题，最终选择少覆盖2题，非参考候选比例略升。应视为有收益也有风险的候选召回改动，不视为已验证的全面性能提升。原文关联正确只说明知识提到了该表，不保证知识适用于当前问题；固定配额下，相关性误判仍可能挤掉必要表。

退步上下文题：6203缺actor，结构修复失败前未进入补检索；3404缺Country，模型在假设中承认缺国家表却未发出可执行gap；3455首轮被冰球守门员知识与案例带偏，板球三张参考表未进入，模型把板球改解释为冰球。同期3432通过补检索补齐Team，抵消其中1题；具体冻结结果见coverage_regressions.json。没有为这些题添加业务规则或特殊修复。

本次任务实际已保存调用：初版v3 68次、v4完整回归217次、v5新调用51次，合计336次、2,519,752 token。v5的200题评测用量1,537,362包含164题复用响应，不代表本次新增用量。v3中断在途调用未保存usage，实际账单可能高于已保存合计；详细分解见billing_summary.json。
