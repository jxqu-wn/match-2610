# 提示词质量评价方案

目标：评价实际发送给生成模型的完整提示词，是否足以支持一个符合题意、业务口径和输出协议的查询，并区分原始资料问题、提示词组装问题和本次模型行为。评价覆盖system、user、必要的历史消息、Schema、knowledge、案例、关系及实际保留的元数据；不只评价模板措辞或召回数量。

采用两层评价：以输入证据质量为主，固定模型的生成对照为辅。表覆盖率、knowledge非空率、模型单次答对率均不能独立代表提示词质量。本文件提出流程与验收，不执行新的LLM请求、数据库查询或生产修复。

## 1. 先建立独立于参考SQL的需求与事实基准

第一批覆盖已有100题的全部实际请求，包括原先60道参考一致题，避免只评价40道非一致题造成选择偏差。这100题属于已反复分析的开发回归集。现有样本有9道跨系统题、没有SQLite，不能据此给出SQLite成绩或稳定估计所有联邦题表现。

由独立评审先阅读题目、统一任务规则、原始Schema及原始knowledge；参考SQL和训练案例只能作为待核对材料，不能直接当全部业务真值。此时不看生成SQL，也不看待比较方案的提示词。先形成并冻结以下内容，再比较各版本提示词：

| 标注内容 | 要求 |
| --- | --- |
| 业务需求 | 对象、过滤、比较边界、时间、统计粒度、去重、公式、单位、输出、排序、空间范围及步骤依赖 |
| 必要事实 | 完成需求需要的结构或业务信息；标记必须、可选、条件性需要 |
| 允许的证据组合 | 相同事实可由Schema、knowledge或经过适用性核验的案例支持；等价查询可使用不同合法表组合 |
| 来源依据 | 文件校验值、JSON路径或行号、原文片段；推导事实需要列出可复现推导，不依赖模型常识猜测 |
| 原始资料状态 | 可明确评价、可接受多个业务解、源资料缺失、题意/规则未决歧义、参考与任务约定不一致 |

例如，BPS公式可以直接来自知识，也可以来自适用于当前业务的正确案例。坐标若可从已提供的度分秒确定性换算，属于可推导；模型凭常识记忆另一组地标坐标，不算提示词已经提供。

存在多个合理业务解时先标注允许范围，不强制与某一条参考SQL完全相同。原始资料无法支持唯一口径、且任务没有规定消歧策略时，列为未决；不能通过多召回一些DDL或默认采用参考答案消除歧义。

对表/字段也允许替代证据组合：只要某个合法查询路径所需证据完整，就不能仅因没召回参考SQL中的另一张表判提示词不充分。旧版“按参考计算的完整库/表覆盖率”保留为辅助指标，明确其边界。

## 2. 逐项核对实际提示词

只检查最终预算裁剪后实际发送的消息；召回池里存在但消息里没有的内容不算已提供。每项必须事实标记：

- `supported`：当前提示词有正确、适用的明确证据。
- `derivable`：可从提示词内证据确定性推导，并给出步骤。
- `missing`：原始资料有可用事实，当前提示词未提供。
- `contradictory`：有影响本题的相互冲突证据，现有优先级无法裁决。
- `unjudgeable`：无法从当前已核定资料作出可靠判断。

原始资料本身没有必要事实，记为源资料缺失，不直接计作检索漏召回。不能因为案例含同一关键词就判为支持，必须核对年份、业务对象、字段、公式、单位、过滤条件和适用前提。

同时按证据片段标记：必要支持、相关背景、无关信息、错误信息、已裁决冲突、未决冲突和未审查。未被参考SQL使用的额外DDL不自动算无关；整张表原文所需的结构上下文可以是相关背景。

冲突需区分三个情况：

1. 同一需求的必要证据未决冲突，会影响本题可回答性。
2. system已经明确规定优先级的冲突，记为已裁决冲突；若旧参考不服从当前协议，另记标签版本错配，不直接判提示词不可回答。
3. 与本题需求无关的残缺或错误内容，记为有害噪声；不能将接触过该知识的每题都判为不可回答。

## 3. 主指标与计算口径

不先压成一个主观加权总分，以完整证据和冲突状态为主要判断，并同时呈现噪声与成本。

| 指标 | 计算或判定 |
| --- | --- |
| 可回答提示词率 | 在业务约定和必须事实均可判定的题中，至少一个合法证据组合完整且没有关键未决冲突的题数/可评价题数 |
| 全集确认可回答占比 | 确认可回答题数/全部抽样题数，连同未决题数报告，避免移除疑难题后抬高比例 |
| 必要事实覆盖率 | 可明确评价的必须事实中，supported或derivable的比例；报告逐题平均和总体计数，未判定事实单列 |
| 完整业务事实覆盖率 | 所有必须事实均有支持的题数/可评价题数；与单条事实平均覆盖分开 |
| 完整结构支持率 | 至少一个合法查询路径所需表、字段、类型及连接信息完整的比例；不要求必须出现全部声明外键 |
| 关键未决冲突率 | 存在影响当前需求、且没有明确优先级可裁决的冲突题数/可评价题数 |
| 无关及错误证据密度 | 已审查为无关、错误的证据token分别占全部证据token的比例，同时报告标注覆盖率、相关背景及未审查占比 |
| 来源保真率 | 实际提示词所保留的原文与来源匹配程度；声明的结构化摘取核对字段，不将有依据的格式转换当改写事实 |
| 可追踪率 | 必要事实能否定位到实际消息及原始依据，是否知道未入选、过滤、排序或裁剪的原因 |
| 上下文成本 | 指令、问题、Schema、knowledge、案例、关系、检索元数据的长度及P50/P95/最大值，另报告是否超预算 |

`unjudgeable`不能直接算已覆盖；有必须事实未判定的题不能计入确认可回答。没有必要knowledge或没有业务知识要求的题，该项记不适用，不能用0/0填100%。同一事实被多个通道重复提供只计一次覆盖，重复占用的上下文另记。

token计量固定同一分词器并记录版本；若不是生成模型的精确分词器，标为比较用统计。证据密度不以system和问题长度作分母，避免额外指令稀释噪声；片段token不重复计数。部分未审查时，已确认无关/错误比例只是下界，不把未审查证据默认算相关。

提示词逐题状态为：

- `answerable`：必要证据充分，无关键未决冲突。
- `missing_evidence`：可用源事实存在，但提示词缺失。
- `unresolved_conflict`：提示词提供的关键证据存在未决矛盾。
- `unjudgeable`：源资料、业务口径或审查信息不足。

缺失与冲突的详细标记允许重叠；汇总状态优先标未决冲突，其次缺失。未判定的必须事实会阻止判为answerable；原始资料未决与审查尚未完成分别记录，不能都称为错误。

## 4. 多库联查必须单列

按系统与业务库关系划分四个互斥分组：同业务库单表、同业务库多表、同系统跨业务库、跨系统联邦；跨系统优先归入联邦组。题型、数据库引擎、空间题等可以另作交叉维度，不把业务库等同于MYSQL/PG系统。

各组均报告上一节指标，并特别检查：

| 场景 | 必须核对的信息 |
| --- | --- |
| 同系统跨业务库 | 每个所需业务库、字典表、连接字段、连接基数与年份范围；不因已有主表就视为完整 |
| 跨系统 | 合法分步方案、每步系统和结构、前一步输出标识、后续result接收字段、类型/单位及必要的去重或聚合语义 |
| 空间及轨迹 | 坐标、轴顺序、坐标参考系、距离单位、区域几何、时间窗口及“先成轨迹还是先筛点”等业务要求 |

允许等价的执行步骤顺序，不机械要求复制参考的MYSQL→PG顺序。边界开闭、空值含义、默认年度未规定时，明确标记业务口径未决，不能从一条参考答案反向制造需求。

联邦题少时展示具体分子/分母和逐题结果；整体平均不能掩盖此组退化。

## 5. 自动检查与独立评审的分工

自动检查负责：实际请求与缓存一致性、来源哈希、表和字段存在性、ID/原文一致性、已标注必须事实的引用位置、裁剪与过滤日志、消息长度、版本关联。它不能仅凭字符串命中证明公式和业务含义正确。

LLM辅助审查或人工负责：必要事实是否定义充分、案例是否适用、替代证据是否等价、冲突是否可裁决、题意是否欠明确。每项结论必须附原文依据和实际消息位置；不足时输出未决，不能凭模型常识补事实。未经人工确认的LLM标签明确保留为辅助标签，不能称作人工金标。

建议先以约20题覆盖完整、缺知识、冲突、噪声、同系统跨库、联邦和源资料未决等情况，校准标注口径；之后对全部100题评价。评审不查看生成SQL或方案名称。采用两个独立审查结果，再裁决分歧；一方为LLM也不能称为两名独立人工。全部关键缺失/冲突、未决、两方分歧均复核，并抽查一致通过题。记录状态一致率及分歧原因，不用评审自报置信度代替证据。

20题口径校准组和已用100题均属于开发数据。新评估按同题/近似模板分组划分，验证题及其答案不进入训练案例池和关联增强；未参与调参的题组才可作独立评估。

生产预处理和检索代码不得读取这些评价标签；知识ID和错题白名单只用于评价报告，不能回写成业务规则。

## 6. 用固定模型对照检验实际影响

输入质量评价完成后，再做生成对照，先固定模型、system协议、路由、表候选、TopK、RRF参数和最终知识预算：

| 对照 | 变更 | 可以回答的问题 |
| --- | --- | --- |
| P0→P1 | 仅解除知识候选资格阻断，保留相同检索参数 | 修复筛选逻辑是否改善提示词事实覆盖及生成结果 |
| 原提示词→诊断补齐版 | 仅补已核定缺失的必要原始事实 | 缺证据是否是当前模型失败的一个因素 |
| 原提示词→去噪版 | 只移除已确认无关/错误干扰，保留必要事实 | 噪声是否影响当前模型利用已有信息 |
| 原提示词→冲突处理版 | 只按既有、已核定优先级显式处理冲突 | 冲突表达是否影响结果；不创造新业务口径 |

诊断补齐版属于离线理想证据对照，不是生产检索成绩；不得放入参考SQL、参考结果或验证集特定答案规则。原始题意/资料尚未核定的题不混入这些可比较对照，先单列澄清。

每种条件建议重复3次，固定采样设置、记录模型标识与时间。温度0的单次结果也不能证明稳定；提示词长度差异单列，需要区分长度与内容影响时再增加等长对照。先做已定位问题的诊断子集，确认方案有效后扩大样本。

如要比较模型，再让两个模型分别接受相同原提示词与相同修复提示词，形成2×2对照。补齐后当前模型改善支持“缺失证据有影响”；同一提示词下另一模型改善支持“本次模型行为有差异”，均不直接证明唯一原因或固有能力上限。

最终查询按业务约定评价，不把SQL字符串相同或执行非空视为正确。能连接数据库时核对结果集、步骤绑定和要求；不能执行时明确为静态语义审查，未决单列。展示每种条件重复结果、配对改善/退化题、各组分母和成本；不靠挑选成功的一次作结论。

## 8. 输出与实施顺序

每题输出需求、必要事实、允许证据组合、来源位置、实际提示词支持位置、缺失/冲突原因、判定状态、原始资料问题与标注者/裁决记录。归因标签区分source、association、filter、ranking、budget、instruction与generation，允许多标签；缺少对照实验时不输出确定的因果占比。

配套文件：

- [完整程序指标及公式](prompt_quality_programmatic_metrics.md)：指标分母、计算方法、设计依据、未知处理和演算示例。
- [评价协议v1](../evaluation/prompt_quality/protocol_v1.json)：冻结状态、口径和评价边界。
- [逐题标注模板](../evaluation/prompt_quality/annotation_template.json)：尚未填充实际题目或评价结论。

建议顺序：冻结实际请求与任务协议 → 核定需求/事实及源资料状态 → 校准标注 → 100题输入质量评价 → 参数不变的P0/P1对照 → 有针对性的补齐/去噪实验 → 未参与调参题组的独立评价。

第一轮报告以“可回答提示词率、必要事实覆盖、关键未决冲突、噪声、成本”并列呈现，不设未经校准的100分加权总分。硬性要求是来源保真、评价依据可追踪、参考与生成隔离；质量改善必须在完整样本、同系统跨库和联邦分组中分别展示。不能把38条地标恢复候选资格或knowledge非空当作提示词质量已经达标。
