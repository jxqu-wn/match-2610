## 关键证据与对上一轮结论的细化

- **245：正确新能源条件已在输入。** 案例155给出了`brand LIKE '%电动%'`，预测改成`'%新能源%'`。这是可见案例未被正确利用，不能归为完全没有知识。
- **2907：正确禁航区已在输入。** 案例2932嵌套SQL包含与参考一致的朝连岛多边形；模型仍说无精确边界并改了经度。2908则确实没有召回日照警戒区定义1742，二者需分别归因。
- **441：不能仅归为BPS知识缺失。** 知识1624未召回，但案例433、439已有正确BPS公式；同时EPS近似知识1635带来干扰。本题归为混合：改善关联有帮助，但原提示词并非完全不含正确公式。
- **2487：缺知识不等于每个概念都缺证据。** 超大规模1709未进入ES提示词；护理1710虽也缺失，案例2473已经补上护理条件且模型用对。决定性输入缺口是超大规模定义。
- **1588：模型遵循新规则。** 系统要求比率ROUND2并优先于案例，案例/参考ROUND4，不能将这条差异归为模型生成错误。
- **2950：单列计数规则作用域过宽。** 规则与参考每船分组不兼容，但尚未做去规则对照；不能声称该规则已被证明是漏分组的唯一原因。
- **1723/1728：两个年份DDL都在。** 题面不含年份，2024或2025没有唯一选择依据，不能说模型路由漏库。

## 如何回答提示词还是模型

将提示词分为三层：召回的事实证据、系统口径/输出契约、案例。上游缺证据不等于改写一句system就能修复；有正确案例仍答错说明本次模型没有正确利用输入，但不证明该模型在所有重试、表达方式或更短上下文中都无法解决。

建议先统一年份、输出对象、地域修饰对象、NULL/空串、空间边界和参考标签，再修复专用知识及必要表的可召回性；最后对证据充分的案例固定同一提示词，对比模型或做重复运行。若做提示词消融，只变动单一字段/规则，不把验证参考SQL或由答案推导的字段白名单传给生成器。本轮没有更改生产策略、参考标签或重新外发数据。
