# 全新50题验证：完全一致与语义一致

2026-10-11。冻结优化版召回/规划逻辑，使用DeepSeek Flash真实测试。本次没有依据这50题再调整提示词、检索或预算后重测。

## 抽样及隔离

从583题验证集中，排除前次20题以及与训练问题经NFKC、大小写、空白/标点规范化后重复的问题，固定随机种子20261011均匀抽取50题。不是按成功结果挑选，也不是各系统等额抽样。

数据库系统输入来自已有训练集拟合的embedding分类器，未把验证集正确数据库标签提供给LLM；本地事后检查50题分类均正确。样本包括SQLite 26题、MYSQL 16题、POSTGRESQL 6题、跨MYSQL/POSTGRESQL 1题、Elasticsearch 1题。

索引审计验证5247条案例与splits/train.json对应，训练/验证ID无交集，catalog附带案例也属于训练集。实际50个最终上下文引用196个不同训练案例ID，非训练案例引用为0。模型获得评测问题、分类预测、schema、知识及召回的训练案例；参考SQL仅生成结束后用于本地评分。没有把原始QA_train全量文件作为案例来源，也没有调用外部模型判断参考答案。

泄露审计见outputs/information_retrieval/live50/leakage_audit.json。

## 指标

| 指标 | 结果 |
|---|---:|
| 完全一致率（所选表集合与参考SQL完全相同） | 41/50，82% |
| 语义一致率（计划级本地逐题审核，明确一致） | 31/50，62% |
| 语义不一致 | 15/50，30% |
| 语义等价无法确认，未计通过 | 4/50，8% |
| 平均表召回率 | 92.33% |

“完全一致”沿用之前的表集合指标，不表示字段、条件或SQL文本完全一致。“语义一致”检查计划能否覆盖参考查询的业务库、关键字段和关系，并检查显式假设是否改变过滤、分组、计数或日期口径。完整schema仍可用于后续投影，未把SELECT *必须逐个列入required_columns作为本模块标准。

生成模块没有输出完整的过滤、聚合和排序结构，故这些分数不是形式化SQL语义等价或执行结果等价率；未明确写出的操作只能评估信息覆盖，不能证明最终SQL一定正确。无证据保证的额外连接和可选口径记为“无法确认”，不直接计为一致。参考疑似错误仍保留在分母，并在逐题记录中标记，不通过剔除样本提高分数。

50题中ready 22、ready_with_assumptions 25、insufficient_evidence 3，无error。可用状态不等于语义正确。

## 主要发现

- 表选对仍可能改口径：4118把“长评论最多的商家所属类别”改成“长评论最多的类别”；1848按课程名称去重，而参考计数匹配行；4288按实际评论条数排名，而参考按Uber级别过滤。
- 关键字段遗漏：3509缺参考比例分母games；2823缺mmsi/timestamp，无法覆盖最新船舶观测口径。
- 选错相似库表：1632在2024/2025课程库间错选；5603把Goalies换为GoaliesSC；445未选择实际包含收入的税务表。
- 仍有真实召回缺口：303缺行业字典，3602缺冠军系列赛表，6112缺影片类别桥表和类别字典。这3题明确返回不足，没有形成可用计划。
- 表集合不完全相同也可能信息等价：887增加非空外键到唯一键的字典关联，明确筛选与COUNT/SUM口径不变，计划级审核通过。
- 额外连接不能默认等价：5694连接多年度Coaches可能复制计数；4191额外Business连接可能过滤原有可空business_id记录。另两题2891、4516的范围或组织/类别替代口径无法确认。

4149、1632、3032、4288存在题面/参考口径疑点，已逐题标记。例如3032的“姓张”在模型中为张%而参考为%张%；模型解释更贴近题面也不能算与参考语义一致。

## 成本与输出

共53次API调用，总输入332842、输出12589、合计345431 token。每调用输入P95为9056、最大9216；输出最大461；没有输出长度截断。继续使用24000总预算/3000输出预留。

实际输出与评分均保存在outputs/information_retrieval/live50：

- selection.json：随机样本及预测分类。
- question_*.json：原始模型响应、最终计划、提供的资料及调用日志。
- report.json：完全一致率、语义一致率、状态与token汇总。
- semantic_review.json：50题人工核查结论、理由、缺失字段和参考疑点。
- local_review_packets.json：本地参考SQL对照；不会作为生成模型输入。
- leakage_audit.json：隔离检查记录。

这一批新样本明显低于优化所用20题的100%表集合匹配，说明先前小样本结果不能代表泛化表现。当前主要问题已从预算裁剪转向需求覆盖、相似表区分和统计口径，而不是单靠继续扩大token额度可以解决。
